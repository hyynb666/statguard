# ML008 — Preprocessing Fitted Separately on Train and Test Sets

ML008 is an additional, post-v0.2 static-analysis rule. It reports a potential
statistical risk when supported data-dependent preprocessing is fitted and
applied independently to the training and held-out test partitions from the
same `sklearn.model_selection.train_test_split` call.

## Evidence and behavior

The rule requires all of the following in one supported analysis scope:

- Both input expressions resolve to train and test roles from the same known
  `train_test_split` record and the same split input index.
- Both sides use the exact same supported sklearn transformer class and have
  proven data-dependent fitting semantics.
- Each side performs an application through `fit_transform`, or through a
  proven same-instance `fit` followed by `transform` on the same stable input
  binding. A refit of the same instance on test data is supported.
- The split precedes both fitting operations. Binding versions and source
  positions come from the existing SymbolResolver and ProvenanceTracker.

The supported classes are `StandardScaler`, `MinMaxScaler`, and `RobustScaler`;
`SimpleImputer` with `mean`, `median`, or `most_frequent` semantics;
`KNNImputer`; supported `IterativeImputer` configurations; and
`SelectKBest`, `SelectPercentile`, and `VarianceThreshold` when the existing
ML003 semantic checks succeed. An explicit constant-strategy SimpleImputer is
not treated as learning data-dependent imputation statistics. Unknown options,
callables, and unsupported signatures cause abstention.

The Finding is a **warning**, **medium confidence**, and **potential statistical
risk**. It points to the test-side fitting call and includes the paired
training-side fit and split locations. Separate fitting may use held-out
distribution information and may put the two partitions into independently
estimated transformation spaces. StatGuard does not establish whether either
output is later used by a model, whether the pattern is intentional, or whether
an evaluation metric changes.

## Example

```python
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler

X_train, X_test = train_test_split(X, random_state=42)
train_scaler = StandardScaler()
test_scaler = StandardScaler()
X_train_scaled = train_scaler.fit_transform(X_train)
X_test_scaled = test_scaler.fit_transform(X_test)  # ML008
```

The same rule applies if one transformer instance is refitted on test data, or
if the fit and transform operations are separate and ProvenanceTracker proves
the same instance and stable input binding.

## Safe example

```python
scaler = StandardScaler()
X_train_scaled = scaler.fit_transform(X_train)
X_test_scaled = scaler.transform(X_test)
```

Here one training-fitted instance transforms both partitions, so ML008 does not
report. A bare `.fit()` without a corresponding observed transform also does
not qualify.

## Limitations

- Split identity, input index, exact class, data-dependent semantics, and both
  applications must be explicit. Variable names are never evidence.
- Different transformer classes, custom transformers, unsupported or dynamic
  calls, unknown mutations, complex control flow, and unresolved bindings are
  outside the rule's scope.
- Pipeline and ColumnTransformer internals, pandas/manual transformations,
  cross-file/cross-function flows, and cross-Notebook-cell flows are not
  analyzed. Notebook cells are analyzed independently; stored outputs are
  ignored and code is never executed.
- The rule does not require transformed outputs to reach a model or metric and
  does not assert actual leakage, invalid results, or performance bias.
- A clean scan is not evidence that preprocessing is statistically correct.

Disable the rule with `statguard check PATH --disable-rule ML008`. It supports
the normal project-level `disable-rules` policy and inline Finding suppression.

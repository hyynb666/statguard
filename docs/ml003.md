# ML003 — Potential Feature Selection Leakage

ML003 reports a statically proven pre-split feature-selection pattern as a
**potential statistical risk**. It does not assert that leakage occurred,
that retained features changed, or that measured model performance is biased.
The rule is enabled by default.

## Required evidence

A warning requires all of these facts in one supported straight-line scope:

1. Symbol resolution identifies an exact public construction of
   `sklearn.feature_selection.SelectKBest`, `SelectPercentile`, or
   `VarianceThreshold`.
2. That exact object receives `fit_transform` with a supported signature, or a
   supported `fit(X, y)`/`fit(X)` followed by `transform(X)` on the same stable
   input binding version.
3. For SelectKBest or SelectPercentile, the score function is the documented
   default `f_classif` or resolves to a supported public sklearn supervised
   score function, and the call explicitly supplies `y`.
4. Provenance traces the transformed X output, optionally through simple
   aliases, into a later resolved
   `sklearn.model_selection.train_test_split`.
5. Evaluation sites prove fitting precedes the split in the same scope, and
   the receiver has not been passed to an unknown call or changed through an
   unmodeled method.

For direct calls, the Finding points to `fit_transform`; for separated calls it
points to `fit`. Both forms include related transform and split locations.
Exact duplicate evidence is collapsed; distinct fit/split pairs remain distinct.

## Statistical meaning

SelectKBest and SelectPercentile rank features using a score function. ML003
supports the known sklearn functions `f_classif`, `f_regression`, `chi2`,
`mutual_info_classif`, `mutual_info_regression`, and `r_regression`.
When X and y from the full dataset are scored before splitting, eventual
held-out samples and labels may influence which features are retained.

VarianceThreshold is different: it learns empirical feature variances from X
and ignores y. If fitted before splitting, eventual held-out feature values may
influence its variance estimates and retained-feature mask. ML003 never
describes this selector as label-dependent.

These are possible information-sharing mechanisms established from source
relationships. Actual data values, retained features, and evaluation effects
remain unknown.

The supported defaults and mechanisms follow sklearn's public documentation:
[SelectKBest](https://scikit-learn.org/stable/modules/generated/sklearn.feature_selection.SelectKBest.html),
[SelectPercentile](https://scikit-learn.org/stable/modules/generated/sklearn.feature_selection.SelectPercentile.html),
and [VarianceThreshold](https://scikit-learn.org/stable/modules/generated/sklearn.feature_selection.VarianceThreshold.html).

## Examples

Reported supervised selection:

```python
from sklearn.feature_selection import SelectKBest, f_classif
from sklearn.model_selection import train_test_split

selector = SelectKBest(score_func=f_classif, k=10)
selected = selector.fit_transform(X, y)
X_train, X_test = train_test_split(selected)
```

Reported unsupervised selection:

```python
selected = VarianceThreshold().fit_transform(X)
X_train, X_test = train_test_split(selected)
```

Not reported because fitting is train-only:

```python
X_train, X_test, y_train, y_test = train_test_split(X, y)
selector = SelectKBest(score_func=f_classif)
X_train = selector.fit_transform(X_train, y_train)
X_test = selector.transform(X_test)
```

Run or disable the rule:

```text
statguard check analysis.py
statguard check analysis.py --format json --fail-on warning
statguard check analysis.py --disable-rule ML003
```

Warnings exit 0 by default; `--fail-on warning` exits 1.

## Conservative boundaries

Unknown or custom score functions, missing/unknown target arguments, positional
selector constructor arguments, `**kwargs`, wrappers, factories, subclasses,
dynamic lookup, unsupported signatures and complex control flow cause
abstention. A coincident class or method name is never enough.

Separate fit/transform requires explicit selector construction, a supported
score configuration, the required target for supervised selection, matching
same-instance state and stable X binding, and straight-line order in one scope.
Refit replaces earlier state; an unknown call receiving the selector or an
unmodeled method invalidates it. Pipeline internals and cross-function,
cross-file or cross-Notebook-cell data flow are not analyzed. Notebook cells
remain independent, and document order does not prove historical execution order.

Module-level imports referenced from a function remain unknown; explicit local
imports work. Mutating or passing the selector object through an unmodeled call
before fitting invalidates the required object-state evidence. Absence of ML003
is therefore not evidence that feature selection is safe.

The implementation never imports sklearn, executes submitted Python or Notebook
code, or reads Notebook outputs. It introduces no runtime dependency or report
schema change.

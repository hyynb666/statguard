# StatGuard v0.2.0

StatGuard v0.2.0 is the current public Alpha release of a conservative static
analyzer for statistical and machine-learning workflow risks in Python and
Jupyter Notebooks. It adds integrations and project policy without adding or
changing detection rules.

## Highlights

- GitHub Composite Action for repository scans.
- Project configuration via `[tool.statguard]` in `pyproject.toml`.
- SARIF 2.1.0 output and guidance for GitHub Code Scanning.
- Console, JSON schema 1.0, offline interactive HTML, and SARIF reports.
- Windows and Linux CI coverage on Python 3.11–3.14.
- Static analysis that does not execute submitted Python or Notebook code.

## GitHub Action

Use the stable release tag:

```yaml
- uses: hyynb666/statguard@v0.2.0
  with:
    path: .
```

The Action writes reports and does not upload artifacts or SARIF automatically.
The caller's workflow controls permissions and upload behavior.

## Project configuration

```toml
[tool.statguard]
exclude = ["generated", "vendor"]
disable-rules = ["ML006", "ST002"]
fail-on = "warning"
```

Only `exclude`, `disable-rules`, and `fail-on` are accepted. Configuration is
read as TOML data, validated strictly, and never executed.

## SARIF

```text
statguard check . --format sarif --output statguard.sarif
```

SARIF 2.1.0 is separate from the unchanged JSON schema 1.0. Notebook cell
coordinates are retained as SARIF properties; StatGuard does not invent line
numbers in the raw Notebook JSON file. See the
[Code Scanning guide](../sarif.md).

## Rules

The enabled rule set remains ML001–ML006, ML009, and ST001–ST002. This release
does not add or change rule semantics.

## Safety

- Python source is parsed statically and never executed.
- Notebook code cells are not executed, and stored outputs are not analyzed.
- HTML finding content is escaped and the offline report uses a restrictive
  Content Security Policy.
- GitHub Action inputs are passed as argument data with `shell=False`; scan,
  config, and output paths are confined to `GITHUB_WORKSPACE`.

## Known limitations

- Rules cover documented patterns that can be resolved statically; unsupported
  or dynamic behavior may be left undetermined.
- Cross-file and cross-Notebook-cell data flow are not modeled.
- Notebook document order does not model kernel execution history.
- Notebook SARIF locations intentionally omit physical raw-JSON line regions.
- A clean scan does not establish statistical correctness.
- The Action does not auto-upload reports or SARIF.

## Installation

StatGuard is not published to PyPI. Install the tagged source or download and
install the wheel attached to the
[v0.2.0 GitHub Release](https://github.com/hyynb666/statguard/releases/tag/v0.2.0).

# StatGuard v1.0.0 (draft)

> Draft release notes for a planned release. This file does not announce that
> v1.0.0 exists. The release, tag, and artifacts require a separate release
> task. StatGuard is not published to PyPI.

StatGuard is a conservative static analyzer for documented statistical and
machine-learning workflow patterns in Python source and Jupyter Notebook code
cells. Findings are review prompts based on source evidence, not proof that an
analysis is invalid.

## Planned highlights

- Recursive `.py` and `.ipynb` scanning without executing submitted code.
- Console, JSON schema 1.0, offline interactive HTML, and SARIF 2.1.0 reports.
- Explicit project policy through `[tool.statguard]` and rule-specific inline
  Finding suppression.
- A composite GitHub Action with workspace-contained inputs and caller-managed
  report upload.
- Eleven default rules: nine ML rules (**ML001–ML009**) and two statistical
  rules (**ST001–ST002**).
- Deterministic scan/report behavior with a reproducible synthetic benchmark
  harness.

## Planned rule set

The audited development rule set comprises ML001–ML009 and ST001–ST002. Each
rule guide documents required source evidence, positive and negative examples,
and abstention limits. The stable v0.2.0 release remains unchanged and does not
include ML007 or ML008.

## Planned GitHub Action use

```yaml
- uses: hyynb666/statguard@v1.0.0
  with:
    path: .
```

This is an example for a future release only. Until that release is separately
published, use the stable `@v0.2.0` reference shown in the README and Action
guide. The Action generates reports but does not upload them automatically.

## Safety and compatibility

StatGuard parses Python with `ast` and reads Notebook JSON as data. It does not
execute Python files, Notebook cells, shell commands, or stored outputs. Project
configuration is parsed as TOML data. HTML escapes dynamic content and is
self-contained with a restrictive Content Security Policy. Action inputs are
passed as arguments without a shell and are constrained to the workspace.

The planned v1 compatibility boundary is documented in
[compatibility.md](../compatibility.md). The current development package is
`0.3.0.dev0`; this draft does not change its version or release metadata.

## Known limitations

- Rules cover only documented static patterns and supported library APIs.
- Dynamic behavior and unresolved relationships are conservatively skipped or
  reported as analysis coverage limits.
- There is no arbitrary runtime introspection, cross-file data flow, or
  cross-Notebook-cell data flow.
- Notebook document order is not evidence of historical execution order.
- Limited sklearn and SciPy APIs are recognized; unsupported APIs are not
  evidence that a workflow is safe.
- A clean scan is not proof of statistical or scientific correctness. Findings
  may need human review and do not prove actual harm.
- The Action does not automatically upload SARIF or reports.
- There is no IDE extension or server/dashboard backend.
- StatGuard is not published on PyPI; no PyPI installation command is provided.

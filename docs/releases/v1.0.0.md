# StatGuard v1.0.0

StatGuard v1.0.0 is the first compatibility-defined major public release and
the current public Beta release. It is a conservative static analyzer for
documented statistical, model-evaluation, and reproducibility patterns in
Python source and Jupyter Notebook code cells. Findings are review prompts
based on source evidence, not proof that an analysis is invalid.

## Highlights

- Eleven default rules: nine machine-learning rules (**ML001–ML009**) and two
  statistical rules (**ST001–ST002**).
- Python and Notebook parsing with conservative import and data-provenance
  tracking; submitted code and Notebook outputs are not executed or analyzed as
  source.
- Rule-specific inline Finding suppression and project policy through
  `[tool.statguard]` in `pyproject.toml`.
- A workspace-contained GitHub Composite Action.
- Console, JSON schema 1.0, offline interactive HTML, and SARIF 2.1.0 reports,
  with GitHub Code Scanning integration guidance.
- A reproducible benchmark harness and deterministic scan/report behavior.
- A defined [v1 compatibility policy](https://github.com/hyynb666/statguard/blob/v1.0.0/docs/compatibility.md)
  for the documented CLI, exit status, rules, reports, configuration, Action,
  suppression syntax, and core Python API.

## Detection rules

The v1 registry enables ML001–ML009 and ST001–ST002 by default. Rule guides
describe the source evidence each rule requires, examples it recognizes, and
cases where it abstains. Detection is limited to supported static patterns;
the rules do not claim comprehensive coverage of statistical or machine-
learning workflows.

## GitHub Action

```yaml
- uses: hyynb666/statguard@v1.0.0
  with:
    path: .
```

The Action writes the requested report and does not upload artifacts
automatically. The caller controls SARIF upload, permissions, and artifact
retention.

## Reports and Code Scanning

StatGuard provides Console, JSON, HTML, and SARIF 2.1.0 output. The SARIF guide
explains how a caller may upload results with GitHub Code Scanning. JSON remains
schema 1.0. The HTML dashboard is self-contained for offline use and escapes
untrusted Finding text under a restrictive Content Security Policy.

## Safety model

Python source is parsed with `ast`; Notebook JSON is read as data, and only
Python code cells are parsed. StatGuard does not import or execute submitted
Python, Notebook cells, shell commands, or report output. Configuration is read
as TOML data. Notebook stored outputs are not passed to rules.

## Compatibility

The v1 compatibility policy covers the CLI and its 0/1/2 exit codes, the 11
rule IDs, JSON schema 1.0, project configuration keys, inline suppression
syntax, GitHub Action inputs, SARIF 2.1.0, and the named `statguard.core`
exports. Other documented implementation modules remain evolving interfaces.
The compatibility policy is at
https://github.com/hyynb666/statguard/blob/v1.0.0/docs/compatibility.md.

## Known limitations

- Rules recognize only documented static patterns and selected sklearn and
  SciPy APIs; dynamic or unresolved behavior may be missed or left unknown.
- There is no arbitrary runtime introspection, cross-file data flow, or
  cross-Notebook-cell data flow. Notebook document order is not execution
  history.
- A clean scan does not prove statistical or scientific correctness. Findings
  may require human review and do not prove actual harm.
- The GitHub Action does not automatically upload SARIF or other reports.
- There is no IDE extension or server/dashboard backend.
- StatGuard is not published to PyPI.

## Installation

StatGuard is not published to PyPI. Install the tagged source:

```text
git clone --branch v1.0.0 --depth 1 https://github.com/hyynb666/statguard.git
cd statguard
python -m pip install .
statguard --version
```

Alternatively, download and install the wheel from the
[StatGuard v1.0.0 GitHub Release](https://github.com/hyynb666/statguard/releases/tag/v1.0.0).

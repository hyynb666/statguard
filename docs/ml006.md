# ML006 — Random split without a fixed seed

ML006 detects a resolved `sklearn.model_selection.train_test_split` call that
uses shuffling but omits `random_state` or sets it to `None`. The finding
records a confirmed code pattern and a potential reproducibility risk; repeated
runs may create different partitions.

## Supported calls and settings

The rule relies on `AnalysisContext.symbols` to establish the exact sklearn
API origin. It supports direct imports and aliases, including:

```python
from sklearn.model_selection import train_test_split

train_test_split(X, y)

from sklearn.model_selection import train_test_split as split

split(X, y, random_state=None)

import sklearn.model_selection as model_selection

model_selection.train_test_split(X, y, shuffle=True)
```

With sklearn's default `shuffle=True`, omitting `random_state` or explicitly
passing `None` can produce a Finding. A literal integer seed, or an integer
constant resolved through the exact binding at the call site, is treated as
fixed. The value `42` has no special status. `stratify` does not make a split
deterministic and does not suppress the rule.

`shuffle=False` is deterministic with respect to shuffling and does not need a
seed for this rule. A statically resolved Boolean alias is supported. Dynamic
`shuffle`, dynamic `random_state`, and `**kwargs` are left undetermined and do
not produce a Finding. A known non-integer literal is not assumed to be a valid
seed. The sklearn API makes split arrays positional and its configuration
parameters keyword-only, so positional array arguments are not mistaken for a
seed or shuffle setting.

## Finding

- **Rule ID:** ML006
- **Severity:** info
- **Confidence:** high when emitted; the API and omitted/`None` setting are
  explicit. The severity reflects that this is an optional reproducibility
  concern rather than a correctness defect.
- **Evidence:** confirmed code pattern

The finding says repeated executions may produce different partitions. It
suggests setting an explicit integer `random_state` **when reproducible data
partitions are desired**. Fixed seeds are not a requirement for statistical
correctness and do not make a model more accurate. Intentionally varying a
split can be appropriate for simulation, sensitivity, or robustness analysis.

## Examples

Potential reproducibility risk:

```python
from sklearn.model_selection import train_test_split

X_train, X_test = train_test_split(X, test_size=0.2)
```

No ML006 finding:

```python
from sklearn.model_selection import train_test_split

X_train, X_test = train_test_split(X, test_size=0.2, random_state=123)
train, test = train_test_split(X, shuffle=False)
```

## Limitations

- Only the resolved sklearn `train_test_split` API is in scope. The rule does
  not inspect NumPy/Python global seeds, other splitters, sampling APIs, model
  estimators' random states, or random search/cross-validation APIs.
- It does not infer the runtime value of helper calls, imported constants,
  `RandomState`/`Generator` objects, dynamic keyword mappings, or values that
  cannot be resolved by the current symbol resolver.
- Function-local and module scopes follow the existing independent symbol
  analysis. There is no cross-function, cross-file, or cross-Notebook-cell
  state. Notebook cells are analyzed independently; document order is not proof
  of execution history.
- Source and Notebook code and stored outputs are never executed or used to
  resolve values.

Disable the rule independently with:

```text
statguard check analysis.py --disable-rule ML006
```

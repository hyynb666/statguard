# ST001 — Potential Multiple Testing Without Correction

**Severity:** warning

**Confidence:** medium

**Evidence:** potential statistical risk

ST001 is a conservative static heuristic. It looks for a supported
`scipy.stats` significance-test call inside a `for` loop, a p-value explicitly
derived from that call, and a comparison of that p-value with a numeric
literal between zero and one in an `if` condition in the same loop. The
finding is located at the comparison.

## Why this may matter

Repeated significance tests can form a family of hypotheses. If each test is
judged against an unadjusted threshold, multiple comparisons may increase the
chance of false-positive findings. Whether correction is appropriate depends
on the inferential target, definition of the hypothesis family, study design,
whether the analysis is exploratory, and the desired statistical control. A
finding does not establish that the analysis is wrong or that a false
positive occurred.

## Supported test sources

The function must resolve through an explicit import binding to one of:

- `scipy.stats.ttest_ind`
- `scipy.stats.ttest_rel`
- `scipy.stats.ttest_1samp`
- `scipy.stats.mannwhitneyu`
- `scipy.stats.wilcoxon`
- `scipy.stats.pearsonr`
- `scipy.stats.spearmanr`
- `scipy.stats.chi2_contingency`
- `scipy.stats.f_oneway`

Direct imports, aliases, and module aliases are supported, including
`from scipy.stats import ttest_ind as test`, `import scipy.stats as stats`,
and `from scipy import stats`. StatGuard reads AST and import bindings; it
does not import SciPy or add it as a runtime dependency. Same-named user
functions and unresolved/rebound imports are not treated as SciPy tests.

## Tracked p-value forms

The initial implementation tracks the second item of a simple tuple/list
unpack from a supported test, aliases of that value, and a `pvalue` attribute
on a result assigned from a supported test. The p-value must be compared
using `<` or `<=` (or the equivalent literal-left `>` / `>=`) against a
numeric literal in `[0, 1]`, such as `0.05`, `0.01`, or `0.1`. A dynamic
threshold, unknown wrapper, unrelated variable named `p`, unsupported unpack
shape, or unconnected result is insufficient evidence.

```python
from scipy.stats import ttest_ind

for feature in features:
    statistic, p = ttest_ind(group_a[feature], group_b[feature])
    if p < 0.05:
        selected.append(feature)
```

An equivalent supported pattern is `result = stats.mannwhitneyu(...)`
followed by `if result.pvalue <= 0.01:`.

## Correction behavior

ST001 does not flag a loop merely because it computes several p-values. For
example, collecting p-values in a list and passing them to an explicitly
imported `statsmodels.stats.multitest.multipletests` call after the loop does
not produce a finding when no unadjusted p-value threshold is used inside the
loop. The rule does not infer a correction from an unrelated call. If raw
p-values are already thresholded inside the loop, a later correction call
does not establish that those earlier decisions used corrected values.

This release does not prove arbitrary association between corrected outputs
and later decisions, inspect correction wrappers, or recognize hand-written
Bonferroni arithmetic. Such cases are outside the current AST pattern.

## Abstention and limitations

- Only `for` loops directly in the module or a supported, independent
  function-local scope are inspected. A non-literal iterable may contain one
  or more values at runtime; its actual cardinality is unknown. Literal
  iterables with at most one element are excluded.
- Calls and comparisons must be connected by a small set of straight-line
  assignments in the loop. Branch-dependent aliases, complex unpacking,
  nested/rebound callables, dynamic thresholds, and wrapper functions are
  unsupported and are not guessed.
- Function-local imports are supported. Module globals are not assumed to be
  the function's runtime binding; unresolved function-scope references are
  skipped.
- No cross-file or cross-Notebook-cell state is tracked. Each Notebook code
  cell is analyzed independently; cell document order is not proof of
  execution history. Notebook outputs are not analyzed.
- Loops establish a possible repetition pattern, not the actual number of
  hypotheses. Corrections outside the analyzed unit and research context are
  unknown.

No finding does not establish that multiple-testing concerns are absent. A
finding is a prompt to review the hypothesis family and analysis design; it
does not require a particular method such as Bonferroni in every setting.
